# Issue tracker — Linear

Issues for this repo live in **Linear**, driven by the STDD skills through the
**Linear MCP**. The board *is* the audience-facing "how we go from one step to the
next" during the live build.

- **Tracker:** Linear
- **Team:** `Agentiwise` (key `AGE`)
- **Project:** `Relay · Lead Scoring`

> Domain docs stay in the repo. `CONTEXT.md` (glossary) and `docs/adr/` (decisions)
> are *not* issues — they live as files and are read before touching an area. Only
> the **issue tracker** and the **PRD** live in Linear. The spike stays a repo file.

## Workflow states ⇄ STDD triage roles

The skills move issues between Linear workflow states. Map them to the canonical STDD
roles (see `docs/agents/triage-labels.md`) — tell `ready-for-agent` from
`ready-for-human` by the **label**, not the state.

| Linear state (type) | STDD role it represents |
|---|---|
| Triage / Backlog (backlog) | `needs-triage` — raw incoming, not yet evaluated |
| Todo (unstarted) | `ready-for-agent` / `ready-for-human` (tell apart by label) |
| In Progress (started) | being built (`/build`, `/afk`, `/swarm`) |
| In Review (started) | `/review` running |
| Done (completed) | shipped |
| Canceled (canceled) | `wontfix` — out-of-scope or already-built |

## Labels

- **Category:** `enhancement`, `bug`
- **Mode:** `afk`, `human-in-loop`
- **State nuance:** `ready-for-agent`, `ready-for-human`, `needs-info`

## Linear-MCP operations the skills use

- **Create issue** (`/slice`, `/triage`, `/afk`, `/swarm`): `save_issue` with the
  `title`, the `description` (the `/slice` issue template), `team` = Agentiwise,
  `project` = Relay · Lead Scoring, `labels`, and `state` = Todo. Number issues in
  dependency order in the title (e.g. `001 · reply → award → badge`).
- **Spec / PRD** (`/write-spec`): `save_document` — a Linear **project Document**
  titled **"Lead Scoring — Spec"** under the Relay · Lead Scoring project. Not an issue.
- **Move state** (`/build`, `/review`, `/afk`, `/swarm`, `/triage`): `save_issue`
  setting the `state` per the mapping table (Todo → In Progress → In Review → Done).
- **Blocked-by DAG** (`/slice`): create Linear **issue relations** of type
  *blocked by* for the dependency edges (e.g. 002 blocked by 001).
- **Triage `wontfix`** (`/triage`): set state **Canceled** and add a `save_comment`
  carrying the "generated by AI during triage" banner with the rejection rationale.
  Mirror the out-of-scope rationale to `.out-of-scope/<slug>.md` in the repo so future
  triage doesn't re-litigate it.
- **Read** (any skill): `list_issues` / `get_issue` to find the issue and its current
  state before acting; `list_issue_statuses` to resolve state IDs for the team.

## Pre-seed (before the session)

Only the **inbox** items are pre-seeded — drop them in **Backlog** with no labels so
`/triage` (phase 09) can categorise them live. Everything else is **created live by a
skill**. The canonical text for every card comes from the `.scratch/lead-scoring/*.md`
and `.scratch/inbox/*.md` files on the demo branches (reproduce them as the Linear
issue description). See `FACILITATOR-RUNBOOK.md` section A for the full issue set.
