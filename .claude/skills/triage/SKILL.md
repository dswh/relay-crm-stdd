# Triage

On-ramp to the STDD flow: turn raw incoming work into agent-ready issues that `/build` later picks up. Use **only** for issues you didn't create — issues from `/slice` are already agent-ready, don't triage them.

If this repo treats external PRs as a request surface (see issue-tracker config), triage covers them too: **a PR is an issue with attached code** — same roles, same states, PR deltas noted below. Resolve a bare `#42` to issue or PR per the tracker config.

Every comment or issue posted during triage **must** start with:

```
> *This was generated by AI during triage.*
```

## Roles

**Category** (one per issue): `bug` (broken), `enhancement` (new feature/improvement).

**State** (one per issue):

- `needs-triage` — maintainer must evaluate
- `needs-info` — waiting on reporter
- `ready-for-agent` — fully specified, AFK-ready
- `ready-for-human` — needs human implementation
- `wontfix` — will not be actioned

Canonical names; actual label strings may differ — the mapping should have been provided (`/setup` if not). Unlabeled → `needs-triage` first, then moves on; `needs-info` returns to `needs-triage` once the reporter replies. Maintainer can override anytime — flag unusual transitions and ask first.

## Invocation

Maintainer invokes `/triage` in natural language ("show me what needs attention", "let's look at #42", "move #42 to ready-for-agent", "what's ready for agents?"). Interpret and act.

## Show what needs attention

Query the tracker, present three buckets oldest-first: **Unlabeled**, **`needs-triage`**, **`needs-info` with reporter activity since last triage notes**. When PRs are in scope, include *external* PRs (per tracker config) tagged `[PR]`/`[issue]`. Show counts and a one-line summary; let the maintainer pick.

## Triage a specific issue or PR

1. **Gather context.** Read the full issue/PR (body, comments, labels, author, dates; for a PR, the diff). Parse prior triage notes so you don't re-ask. Explore the codebase via the domain glossary, respecting ADRs. Run two checks: (a) **redundancy** — search for an existing implementation by domain concept, report where you looked (if found, it's an already-implemented `wontfix`); (b) **prior rejection** — read `.out-of-scope/*.md`, surface anything resembling this request.
2. **Recommend** category + state with reasoning and a brief codebase summary. Wait for direction.
3. **Verify the claim.** Bug: reproduce from the reporter's steps. PR: check it out, run relevant tests/commands. Report confirmed (with code path), failed, or insufficient detail (a strong `needs-info` signal). Confirmed verification = stronger brief.
4. **Align (if needed).** If the request needs fleshing out, run `/align` — one question at a time, sharpening terms and updating `CONTEXT.md`/ADRs inline.
5. **Apply the outcome:**
   - `ready-for-agent` — post an **agent brief** comment (template below).
   - `ready-for-human` — same structure, but note why it can't be delegated (judgment, external access, design, manual testing).
   - `needs-info` — post triage notes (template below).
   - `wontfix` — close: if **already implemented**, point to where it lives (do not write to `.out-of-scope/`); if **rejected**, write a short rationale to `.out-of-scope/<slug>.md`, link it from the closing comment.
   - `needs-triage` — apply the role; optional comment for partial progress.

`.out-of-scope/` is a small knowledge base of *rejected* enhancement requests so future triage doesn't re-litigate them.

## Agent brief template

```markdown
> *This was generated by AI during triage.*

## What to build
End-to-end behaviour for this slice (domain language; no stale file paths).

## Acceptance criteria
- [ ] ...

## Context the agent needs
Relevant modules/seams, prior art, constraints, confirmed reproduction (for bugs).

## Blocked by
- ... (or "None — can start immediately")
```

## Needs-info template

```markdown
> *This was generated by AI during triage.*

## Triage Notes
**Established so far:** ...
**Still needed from you (@reporter):** specific, actionable questions — not "please provide more info".
```

## Quick override

If the maintainer says "move #42 to ready-for-agent", trust them: confirm what you'll do (roles, comment, close), then act. Skip aligning; if moving to `ready-for-agent` without one, ask whether they want a brief written.
